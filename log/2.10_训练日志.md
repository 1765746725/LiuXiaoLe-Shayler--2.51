> **小模型不需要课程学习。所有数据从 step 0 均匀加权，让优化器自然分配参数容量，比先窄后宽的课程学习更有效。**

## 2.7 v23-c：FP32 诊断（❌ 废弃）

### 核心改动
- 移除 `torch.amp.autocast('cuda', dtype=torch.bfloat16)`，直接 FP32 前向+反向
- `torch.set_float32_matmul_precision('highest')` 最高精度
- 其余不变（bias=True, wd=0.01, NS=5, λ=0.4 固定, 202 文件, 60/37/3）

### 实际运行
- **step 10-20**：gn=**1.2**，ema=10.16 → FP32 生效，梯度突破 0.3 天花板
- **step 120-130**：gn=**1.0**，ema=9.13 → 健康下降
- **step 270-280**：gn=**0.5**，ema=7.70 → 开始衰减
- **step 460-500**：gn=**0.4**，ema=7.69 → **完全停滞**
  - step 270→470 共 200 步，ema 仅降 0.01

### gn 全程趋势
```
步数:  10  ──── 130 ──── 280 ──── 470
gn:    1.2  →  1.0   →  0.5   →  0.4
ema:  10.16 → 9.13  → 7.70  → 7.69 (停滞)
```

### 结论
**BF16 是帮凶，不是主犯。** FP32 把 gn 起点从 0.3 拉到 1.2，证明 BF16 精度确实压制了梯度。但 gn 随后持续衰减至 0.4，ema 在 7.69 停滞——与 BF16 版本一模一样的停滞模式。FP32 只延缓衰减速度，不能消除。根因尚待 v23-d 进一步排查。

- FP32 精度（单变量诊断），500 步

### 实际运行

## 2.7 v23-f：纯 AdamW（✅ MuonAdam 确认为元凶）

### 核心改动
- **去掉 Muon**：MuonAdam → 纯 PyTorch AdamW
- 全部参数用 AdamW（β1=0.9, β2=0.95, lr=3e-4, wd=0.01）
- 其余完全不变（StdAttn、8K Vocab、BF16、bias=True、3 个 .pt）

### 假设
> MuonAdam 中 Muon（μ=3e-3）和 AdamW（α=3e-4）LR 相差 10 倍，且 Muon 需要 Newton-Schulz 正交化。如果 NS 在高维矩阵上引入噪声，或双优化器更新方向冲突→有效梯度削弱→gn 塌缩。纯 AdamW 单优化器无此问题。

### 实际运行（500 步）

**gn 全程走势：**
```
warmup: 1.0 → 0.4 → 0.6 → 0.4（震荡，和之前版本一致）
满 lr:  0.8 → 0.9 → 1.1 → 0.9 → 1.0 → 1.4 → 1.2 → 1.7 ↗ 峰值
后期:   1.7 → 1.0 → 0.7 → ... → 0.5 ↘ 轻微回落（数据过拟合）
```

**关键指标：**
| 指标 | v23-f (AdamW) | 之前 MuonAdam 版本 |
|------|:---:|:---:|
| gn 峰值 | **1.7** | ≤1.4 |
| gn 均值(满lr后) | **~0.85** | ~0.5 |
| gn 死区(<0.5) | 末尾零星出现 | 200 步后持续 |
| 末期 loss ema | **4.9** | 6-7 |
| 末期 gn | 0.5 | 0.3-0.4 |

| v23-e | 8K 词表 | BF16 | 2.4 | 0.5 | ❌ vocab 无罪 |
| **v23-f** | **纯 AdamW** | **BF16** | **1.7** | **~0.85** | **✅ 元凶确认** |

**不变式的打破：** 之前八个版本 gn 全部收敛到 0.3-0.5 死区。v23-f 是唯一一个 gn 均值维持在 0.8+ 的版本，且峰值 1.7 创所有版本新高。

### 机制分析

Muon 在 2D 参数上大步长（μ=3e-3，是 α=3e-4 的 10 倍），通过反向传播链扰动 1D 参数的梯度场：
1. 2D 层输出幅度由 Muon 的大步长主导 → 输出分布持续漂移
2. 1D 层梯度依赖于 2D 层输出 → 梯度方向随 Muon 更新而震荡
3. 双优化器虽然参数不重叠，但梯度通过前向计算耦合
4. 纯 AdamW 所有参数统一 lr=3e-4 → 梯度场一致 → gn 稳定

### 结论
**MuonAdam 双优化器交互是 gn 衰减的根因。九个变量全部排查完毕，唯一有效的变量是去掉 Muon。**

末尾 gn 从 1.7 回落到 0.5 判断为 3 个 .pt 小数据集过拟合（源 0 循环 2 次），非架构问题。

| 指标 | v28（原版） | v29a（极简, LR=3e-4） | **v29b（LR=1e-4）** |
|------|:---:|:---:|:---:|

| ema@1000 | ~4.78 | ~4.79 | **4.98** |

### 反直觉结论

**LR=1e-4 的 gn 更健康（warmup 峰值 4.5 vs 2.4），但 ema 终点反而更高（4.98 vs 4.79）。**

这说明：
1. **gn 绝对值不是有效监控指标**——高 gn ≠ 好收敛，低 gn ≠ 死区
2. **3e-4 在 8K 词表下并不过高**——反而是 1e-4 学习太慢，1000 步还没到位
3. **v28 用 3e-4 + QK-Norm + GQA 拿到 4.65**——QK-Norm/GQA 对收敛有正向帮助，不是 bug
4. **LR 不是 gn=0.3 的根因**——降低 LR 只延缓了 gn 衰减，没有阻止 ema 天花板

### 裁决：LR 已排除

降低 LR 三个好处（warmup gn 更活跃、满 lr 后 gn 更高、ema 下降更平滑），但最终 ema 更差。**LR 是缓解因素，不是根因。**

真正的天花板在别处——数据有效信号密度、BF16 精度、或模型架构本身的容量限制。

#### 多助手标签设计

模型训练后会认识三个称呼都是自己，推理时用哪个都能正常响应。同对话内标签保持一致。

### v30 SFT Stage 1 — 最终结论（2026-07-06）

**训练状态：** 10608 / 22000 步（48.2%），已停止。

**表面数据：** ema 从 5.0 → 3.59（停滞） → 2.66（"救回来"），看起来在收敛。

**实际情况：模型已死。** 使用训练原生格式（`用户：`/`小乐：`）测试，输出全是 `#` `*` `\n` `步骤` `设计` `选择` 等格式化碎片，无法形成任何有意义的对话。

#### 决定性证据

给定 prompt `用户：你好`，模型应预测 `小`（`小乐：` 的第一个 token，id=3560）。实际 top-10 预测：

| 排名 | token | logit |
|:---:|------|:-----:|
| 1 | `的` | 4.52 |
| 2 | `设` | 3.50 |
| 3 | `<pad>` | 3.34 |
| 4 | `在` | 3.30 |
| 5 | `打` | 2.83 |
| 6 | `。` | 2.66 |
| 7 | `地` | 2.59 |
| 8 | `*` | 2.58 |
| 9 | `选` | 2.47 |
| 10 | `按` | 2.33 |

**`小`（id=3560）根本不在 top-10 中。** 训练 10608 步后，模型不认识对话格式。

#### 现象解释

Loss 从 3.59 降到 2.66 不是模型学会了对话，而是学会了 "loss 作弊"：
- MiniMind SFT 数据中大量 markdown 教程/攻略内容（`#`/`*`/`步骤`/`设计`/`选择` 等）
- 这些 token 在数据中高频出现，分布在 assistant 回复中
- 模型发现输出这些格式化 token 就能把 masked loss 降下来
- 但从未学会对话结构——连最基本的 "用户说完后该输出小乐：" 都没学到

**这解释了之前观察到的奇怪现象：** gn 从 0.2 跳到 1.0+ 不是因为模型"开窍了"，而是找到了高频格式化 token 这条梯度信号更强的捷径。

#### v30 最终结论

| 阶段 | 状态 | 结果 |
|------|:---:|------|
| v30b Base | 🔴 | ema=3.22，数学题模式坍塌 |
| v30 SFT Stage 1 | 🔴 | ema=2.66 但输出格式化垃圾，模型未学到对话 |

**根因：MiniMind 数据全链路质量差**
- Pretrain 数据：数学应用题占比过高 → Base 模式坍塌
- SFT 数据：markdown 教程类内容过多 → 模型学格式化 token 而非对话

**教训：** Loss 下降 ≠ 模型变好。Base 模式坍塌 + SFT 数据质量差 = 双重打击，此路不通。

**v31 方向（2026-07-07 确定）：** 直接用 MiniMind 原版数据重训。Base 数据只用 MiniMind pretrain（去掉 Industry），SFT 数据原样使用 MiniMind sft_t2t。MiniMind 作者已验证这套数据可行，v30 的失败更可能是随机种子或其他偶然因素。换种子重跑一次。

## Stage 2a v2：系统角色 + 低LR高循环重训（🟢 2026-07-12 就绪）

### 背景

**v1（800步，lr=1e-5）结果：** 200步测试——人格学会（语气/风格正确），身份未学会（不知道自己是柳小乐）。700步后 loss 震荡回升（ema 从 2.05→2.20），过拟合。

**根因分析：** 方案 B 只用 `assistant：` 标签，身份信息和普通对话在结构上无区分。"我叫柳小乐" 和 "今天天气真好" 对模型来说都是 assistant 回复——模型学会了怎么说话（人格），但学不会"assistant 这个角色到底是谁"（身份）。

### v2 改进

| 改动 | v1 | v2 | 原因 |
|------|:---:|:---:|------|
| 系统角色定义 | ❌ 无 | **✅ `system：你是柳小乐，你可以自称柳小乐、小乐或阿乐...`** | ★ 核心：身份有结构锚点，每次生成前模型都看到角色定义 |
| lr | 1e-5 | **5e-6**（Stage 1 的 1/20） | 进一步降低，保护对话能力 |

### 训练过程

| 步数 | loss | c_lp (chosen) | r_lp (rejected) | 差距 |
|------|------|:---:|:---:|:---:|
| 1 | 0.69 | -3.23 | -2.47 | -0.76（模型略偏好 rejected） |
| 25 | 0.66 | -3.54 | -3.47 | 0.07 |
| 50 | 0.49 | -3.84 | -7.69 | **3.85** |
| 75 | 0.17 | -6.56 | -22.96 | **16.4**（强偏好 chosen） |
| 600 | 0.0025 | -4.4 | -63.4 | **~59** |

### 结果（🔴 模型崩塌）

**75 步已经出现崩塌前兆（r_lp=-23），300 步 checkpoint 测试同样过拟合。**

**测试表现：** "你好" → 输出 "我我我我我我我我……"（无限重复单 token）

## v3 Phase 1 实测评估（🔴 不合格 · 2026-07-12）

用 `chat.py` 加载 `stage2_step_000500.pt` 进行多轮身份测试：

### 发现的问题

**1. `assistant：` 标签泄漏（严重）：**

被直接问"柳小乐"时不承认，只认"小乐"。名字认知不完整。

### 结论

**v3 Phase 1 实测不合格。** 15% 身份数据 + `system：` 标签确实比 v2（80% 崩塌）好，但仍然有格式泄漏和身份回避。`system：` 标签对 294M 模型本质上是有害的——Stage 1（25600步）从未见过它，任何比例都会造成格式扰动。

### Phase 1b 续跑尝试（🔴 更差）

**教训：续跑时改 max_steps 会破坏 cosine LR schedule，必须从头开始。**

## v31 重训——清洗 Base 数据（✅ Base 完成 · 2026-07-13 → 2026-07-14）

### OOM + 代码回退

首次启动使用原 v31 notebook 的优化配置（ckpt_group=20 禁用重算 + fused AdamW），立即 OOM：

```
HIP out of memory. Tried to allocate 4.00 GiB. GPU 0 has 191.69 GiB total, 894.00 MiB free.
```

**根因：** ckpt_group=20 下 20 层注意力的 `[128, 16, 1024, 1024]` 矩阵全部保留，仅注意力 score 就 80GB+，加上 FFN 激活和优化器状态 → 超过 192GB。

|------|:---:|:---:|
| ckpt_group | 20 | **2** |
| AdamW | fused=True | **标准** |
| torch.cuda.synchronize | 无 | **8 个** |
| gc_collect | False | **True** |
| empty_cache_steps | 2000 | **200** |

### 核心发现

1. **清洗有效但不够彻底。** 34 条正则移除了第一人称声明，但第三人称科普中 `通义千问` 与 `AI` 的共现信号仍能教会模型身份槽位填充——10000 步的证据。

2. **Cosine LR 是天然的平滑器。** 后半段 lr 3e-4→3e-5，数据循环第二轮，通义千问被更多样化的命名实体稀释，身份映射自然消失。不需回头洗 Base 重训。

## v31 SFT Stage 1 C 路径 — 第一次训练（🔴 500 步崩塌）

**日期：** 2026-07-15

**配置：**

**训练输出（DSW MI300X）：**
```
10/25300 loss=0.9312 ema=1.0147 [WARMUP]
20/25300 loss=3.6538 ema=1.1285 [ID] ← 首次身份 step，loss 跳升正常
```
500 步 chat.py 测试：
```
prompt> 你叫什么？
柳小乐，柳树的柳，大小的小，快乐的乐。朋友都叫我阿乐或者小乐...
[常识]
今天天气真好，阳光明媚，空气清新。我是柳小乐，朋友们都叫我阿乐或者小乐~
柳小乐，柳树的柳，大小的小，快乐的乐。  ← 重复 5 次！
```

### 崩塌诊断

三个症状：
1. **角色混淆**：模型替 user 说话（"你有什么故事？有什么问题吗？"）
2. **严重重复**："柳小乐，柳树的柳，大小的小，快乐的乐" 连续输出 5 次
3. **`[常识]` 标签**：输出中出现了 `[常识]` 标签前缀

**`[常识]` 溯源：** 经排查，`[常识]` 来自 `eval.py:408` 的测试 prompt `("常识", "今天天气真好，")`，模型在崩塌状态下续写了它。不是训练数据残留——sft2_data 所有文件中没有 `[常识]` 括号标签，只有自然用语（"反常识""常识判断"）。

**Base/SFT 数据确认：** Base 预训练数据和 SFT 一阶段数据均已按 `clean_sft_identity.py` 规则清洗过 MOSS/通用 AI 身份。

### 根因确认：身份 QA 数据模板重复

排查 `sft_identity_qa.jsonl`（3004 条），发现系统性模板重复：

| 5-gram 片段 | 出现次数 | 占比 |
|---|---|---|
| "自由插画师" | 1622 | 54% |
| "叫我阿乐就" | 1203 | 40% |
| "叫我阿乐就行" | 1113 | 37% |
| "叫我小乐，" | 1062 | 35% |

**根因链：**
```
generate_identity_qa.py + generate_sft.py
    ↓ 5 路并发，同一份角色卡，同一 system prompt
每路独立调用 LLM，互不知对方生成了什么
    ↓
LLM 每次都从角色卡挑最明显的标签输出
  "柳小乐，柳树的柳，大小的小，快乐的乐"
  "自由插画师一枚" / "叫我阿乐就行~"
    ↓
3004 条中这 3 句话各出现 1000-1600 次
    ↓
C 路径每 20 步喂一次 → 500 步=25 次曝光
    ↓
模型背下来 → 任何对话触发重复输出 → 崩塌
```

**不是 MOSS 污染、不是 `[常识]` 标签泄露、不是 5% 比例问题。**
根因是 **LLM 生成的数据天然有模板化倾向**，3004 条看似多样实则高度重复。

同样的问题存在于所有 `sft2_data` 文件（全部是同一 LLM 管线生成）：
- `sft_humor.jsonl`：最高频 5-gram 出现 **1979 次**
- `sft_daily_chat.jsonl`：最高频 5-gram 出现 **1523 次**
- `sft_meme.jsonl`：最高频 5-gram 出现 **1442 次**

### 全量数据清洗

创建 `clean_sft2_dedup.py`——基于**模板 n-gram Jaccard 相似度**的去重：

**算法：**
1. 全局扫描：统计每个 5-gram 出现在多少条对话中
2. 标记"模板 5-gram"：在 ≥5% 条目中出现的 → 认定为模板片段
3. 每条对话只保留模板 5-gram 构成"模板指纹"（过滤掉不同上下文）
4. 模板指纹 Jaccard > 阈值 → 判定为重复 → 丢弃
5. 优先保留内容更长的版本

**阈值配置：**
- identity 类（identity_qa / identity_gentle）：0.25
- 其他文件：0.30
- DPO 文件：0.25（兼容 `prompt`/`chosen`/`rejected` 格式）

**清洗结果：**

| sft_deep_talk | 2020 | 196 | 90.3% |
| sft_longform | 1534 | 259 | 83.1% |
| sft_sky_nature | 1501 | 405 | 73.0% |
| dpo_pairs | 2710 | 2539 | 6.3% |
| **总计** | **~30K** | **~8.9K** | **70%** |

DPO 文件仅砍 6.3%（chosen 回复天然多样化，rejected 全是同一句机器模板成了纯净负样本）。

### 测试记录

| 测试 | 数据 | lr | 步数 | 结果 |

| v5 第一次 | 15198 条（daily_chat 9106=56%）| 1e-6 | 20 | 触碰"柳小乐"崩塌、"阿乐"死灰复燃、输出随机人名（李明/张华/王丽）|

| v5 第三次 | 6804 条（identity_qa 1000=14.7%）| 5e-6 | 41 | loss=1.53 ema=4.42 gap=2.9× → 过拟合 |

### 根因

```
Base step_015000 底层权重含旧身份（通义千问/阿乐/MOSS）
    → SFT Stage 1 用 assistant：标签，未注入柳小乐身份
    → Stage 2 用 柳小乐：标签突然注入 = 与底层权重直接对抗
    → 模型在"柳小乐" token 附近崩塌
```

**核心结论：身份不能靠 Stage 2 "冲刺"注入。必须在全链路（Base→SFT→Stage 2 兜底）中自然分布。**

### 数据配比教训

- identity_qa 占比过高（33%）→ 过拟合
- identity_qa 占比过低（0.1%/2.5M）→ 信号被淹没
- daily_chat 占比过高（56%）→ 稀释身份信号
- **关键：身份数据应该均匀稀疏分布在海量通用数据中，而不是集中堆叠**

#### LR 调优历程

| 尝试 | LR | 结果 |
|------|:---:|------|
| 1st | 4e-5 | 🔴 100 步崩塌 — 重复循环 + `Outlo：` 碎片 |
| 2nd | 1e-5 | ✅ 500 步恢复 · 1400 步最佳 — 柳小乐身份 + 对话流畅 |
| 3rd（续跑） | 5e-6 cosine | ⚠️ gn=0.38 但 LR 被 cosine 压到 9.8e-7 |
| 4th（续跑） | 2e-6 恒定 | ⚠️ gn 稳定但 2000 步过拟合 — 知识/创作退化 |
| **最佳** | **1e-5 · 1400 步** | **★ 身份认知 + 对话平衡最优** |

#### 结论

- **1e-5 是 Stage 2 的最佳 LR**：4e-5 导致灾难性遗忘，5e-6 太慢
- **1 epoch 已足够**：续跑 0.5 epoch 开始过拟合
- **最佳 checkpoint：`sft2_step_001400.pt`**（或 1421）
- **梯度检查点（ckpt_group=2）** 对 Stage 2 训练无负面影响
