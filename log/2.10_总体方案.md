## 一、项目目标

**从零训练一个 294M 的柳小乐角色内化对话模型，能进行自然多轮中文对话。**

成功标准：
- 10 轮对话测试中 ≥ 7 轮产出合理回复
- 身份问题正确回答（"你是柳小乐？"→"对，我是柳小乐"）
- 多轮对话不跑偏、不循环、不退化

## 三、模型架构（294M）

### 3.1 规格

| 参数 | 值 | 说明 |
|------|:---:|------|
| n_layer | 20 | Transformer 层数 |
| n_embd | 1024 | 隐藏维度 |
| n_head | 16 | 注意力头数，head_dim=64 |
| n_query_groups | 4 | GQA 4 组，KV 头=4 |
| intermediate_size | 3584 | SwiGLU FFN 中间维度 |
| block_size | 1024 | 最大序列长度 |
| vocab_size | 8K (~13K) | Metaspace BPE，从分词器自动读取 |
| **参数量** | **~300M** | 含词表 |

### 3.2 架构组件

```
Embedding (vocab × 1024)
  ↓
×20 Block
  ├── RMSNorm → StdAttn (GQA) → Residual
  └── RMSNorm → SwiGLU → Residual
  ↓
RMSNorm → Linear Head (1024 × vocab)  ← tied with Embedding
```

| 组件 | 实现 | 说明 |
|------|------|------|
| 注意力 | **StdAttn + GQA** | 标准 MHA，16 heads / 4 KV groups（v23-h 确认 DiffAttn 副犯 $0.36，v51 全链路使用 StdAttn） |
| QK-Norm | RMSNorm on Q, K | 防注意力 logit 爆炸 |
| FFN | **SwiGLU** | output = W3(silu(W1(x)) ⊙ W2(x)) |
| 位置编码 | **RoPE** | base=10000，预计算 cos/sin buffer |
| 归一化 | **Pre-Norm RMSNorm** | — |
| 词表绑定 | **Tied Embeddings** | emb.weight = head.weight |

### 3.3 优化器：AdamW

**v23-f 确认 MuonAdam 是 gn 衰减主犯。2.8 改用纯 PyTorch AdamW。**

| 参数 | 值 | 说明 |
|------|:---:|------|
| 优化器 | **torch.optim.AdamW** | 所有参数统一优化 |
| lr | 3e-4 | 恒定（warmup 后） |
| β | (0.9, 0.95) | — |
| weight_decay | 0.01 | — |
| grad_clip | 1.0 | — |

## 四、训练流程（v51 实际执行）

### 三阶段训练

```
① Base 预训练（v5.1 · 清洗数据 · 纯文本）
   数据：MiniMind pretrain → 6 步清洗（去 AI 身份/代码/英文/外文）
   分词：MiniMind 8K BPE（fertility 0.699）
   架构：StdAttn + GQA 4KV + QK-Norm + SwiGLU · 294M
   AdamW lr=3e-4 Cosine→3e-5 | 15000 steps | batch=128
   数据量：~1.90B tokens · 94 个 .pt · ~1 epoch
   显存：~4.3GB · 速度：~7s/步
   ↓
   checkpoints_v51/step_015000.pt（ema≈1.15）

② SFT Stage 1 — 纯对话训练（~27h）
   数据：MiniMind SFT → v8 清洗（9 条规则）→ tokenize → 256 个 .pt
   从 v5.1 Base 续训 | AdamW lr=5e-5 Cosine→5e-6 | 13592 steps | batch=128
   格式：conversations（user/assistant）· masked loss（仅 assistant）
   架构/精度/ckpt 与 Base 完全一致
   ↓
   checkpoints_sft1_v51/sft_step_013592.pt
   学会「怎么对话」

③ Stage 2 — 混合身份注入（~1.5h）
   数据混合：Stage 1 抽取 163,620 条（90%）+ 柳小乐身份 18,180 条（10%）
   从 Stage 1 续训 | AdamW lr=1e-5 Cosine→1e-6 | 1421 steps（~1 epoch）
   ★ 最佳 checkpoint：sft2_step_001400.pt
   ↓
   学会「我是柳小乐」
```

### 与旧方案的关键差异

| | 旧方案（v31 C 路径） | v51 实际 |
|------|------|------|
| Base 数据 | MiniMind 原样（含 AI 身份） | **6 步清洗（去 AI 身份）** |
| Base 步数 | 20000 | **15000（~1 epoch）** |
| SFT 数据 | v6 清洗 · 混 5% 身份 QA | **v8 清洗 · 纯对话（身份留给 Stage 2）** |
| Stage 2 数据 | 独立身份文件（~24K 条） | **9:1 混合（身份均匀稀疏分布）** |
| Stage 2 方式 | 集中注入（身份数据堆叠） | **混合注入（身份数据均匀分布在通用数据中）** |
| 标签 | system/user/assistant 三标签 | **user/assistant 两标签** |
| 身份标签 | 多标签 5:3:2（训练时随机替换） | **仅「柳小乐」** |
| 阶段数 | 4（Base→SFT1→SFT2→Identity） | **3（Base→SFT1→SFT2）** |

### 为什么两阶段 SFT 就够了

旧方案将「学会对话」和「学会身份」分成 Stage 1 + Stage 2 + Identity 三个阶段。v4.x/v31 的失败证明：

- **身份不能靠 Stage 2「冲刺」注入。** Base 底层权重含旧身份时，Stage 2 集中灌入柳小乐 = 两个身份打架 → 崩塌
- **身份也不能靠 Stage 1「混入」解决。** C 路径 5% 身份 QA 混入 → 模板重复 → 500 步崩塌

v51 的正确做法：
1. **Base 阶段彻底清洗旧身份** — 从地基开始就没有 MOSS/通义千问/阿乐
2. **Stage 1 纯对话** — 只学「怎么说话」，不碰身份
3. **Stage 2 混合注入** — 身份数据（10%）均匀稀疏分布在通用对话（90%）中，lr=1e-5 低强度注入

关键洞察：**身份数据应该均匀稀疏分布在海量通用数据中，而不是集中堆叠。**

## 五、v22 Base 预训练方案（MiniMind 风格）

### 5.1 核心决策

v21 的问题：课程学习 P1（26 CCI3 独占 3000 步）→ 5000 步 loss 停滞 6.3。小模型容量有限，单源独占导致参数空间利用率低——20% 的数据激活 20% 的参数，剩下 80% 空转。

v22 的方案：**对标 MiniMind，所有数据从 step 0 可用，加权随机采样，无阶段划分。**

**★ 对标依据：** MiniMind（64M-108M）不需要课程学习——所有数据从 step 0 均匀喂入，1-2 epoch 收敛至 loss ~2.0。小模型的瓶颈是数据充分性，不是课程顺序。

```
全阶段统一（step 0 → 20000）：
  数据：CCI3 60%（120 文件）+ Industry 37%（80 文件）+ Math 3%（2 文件）
        = 202 文件 ~1.01B tokens，各 ~2.6 epoch
  采样：每步独立加权随机抽源 → 优化器动量自然平滑混合
  LR：muon 3e-3 全阶段（warmup 500 步）
  预期 loss：~11 → ~6（1000步）→ ~4（5000步）→ ~3（20000步）
```

### 5.2 关键差异 vs v20/v21

| | v20 | v21 | **v22** |
|------|------|------|------|
| MiniMind | 24%（英文干扰） | 0% | **0%（Base 纯中文）** |
| 数据策略 | 固定块状轮换 | P1 CCI3 独占 → P2 加权 | **全阶段加权随机** |
| Phase 切换 | 无（混乱轮换） | ema<5.0 / step≥8000 | **无 Phase** |
| 文件数 | 403（四源） | 130（P1 26→P2 104） | **202（全阶段统一）** |
| 各源 epoch | ~0.5 | P1~5 / P2~3（不均衡） | **各 ~2.6（均衡）** |
| LR | muon 5e-3 | P1 2e-3→P2 3e-3 | **3e-3 全阶段** |
| 总步数 | 16000 | 20000 | **20000** |
| 文件删除 | 是 | 否 | **否** |
| Industry 品类 | 6 类（重叠 CCI3） | 6 类 | **3 类（互补 CCI3）** |

### 5.3 v22 数据文件配比

```
CCI3:      120 文件 × 5M = 600M tokens  → 1.572B / 600M = 2.6 epoch ✓
Industry:  80 文件 × 5M = 400M tokens   → 0.970B / 400M = 2.4 epoch ✓
Math:      2 文件 × 5M = 10M tokens     → 0.079B / 10M  = 7.9 epoch（仅 3% 步数）

总计: 202 文件 · ~1.01B tokens · 平均 2.6 epoch
```

**Industry 3 类：**

| 类别 | raw 大小 | 作用 |
|------|:---:|------|
| `literature_emotion` | ~5.0 GB | 文学/情感 — 柳小乐角色核心表达 |
| `mathematics_statistics` | ~0.3 GB | 数学推理 — 补充 Math 源 |
| `artificial_intelligence_machine_learning` | ~0.2 GB | 技术精确表达 — CCI3 稀缺资源 |

### 5.4 采样机制：加权随机 vs 块状轮换

```
v20 块状轮换（失败）：
  [CCI3×5] → [Industry×3] → [MiniMind×3] → [Math×1] → 循环
  问题：连续同源步导致梯度方向突变，动量冲突

v22 加权随机（对标 MiniMind）：
  每步：random() → <0.60→CCI3 | <0.97→Industry | else→Math
  效果：梯度方向在批量间平滑混合，动量自然平均
  依据：MiniMind 用此策略将 64M 模型 loss 从 8.8 降到 2.0
```

### 5.5 ROCm 必要配置（MI300X 192GB）

| # | 配置 | 说明 |
|---|------|------|
| 1 | 手写 DiffAttn | ROCm 无 Flash Attention 内核 |
| 2 | softmax 不加 `.float()` | 加了 OOM（fp32 显式拷贝） |
| 3 | checkpointing **ON**（2层一组） | 294M 必须开，否则 192GB 不够 |
| 4 | `precision='medium'` | AMD 无 TF32 张量核心 |
| 5 | `num_workers=0` | ROCm DataLoader 多进程死锁 |
| 6 | `expandable_segments:True` | 防显存碎片 |
| 7 | `max_split_size_mb:512` | 同上 |
| 8 | 不设 `HSA_OVERRIDE_GFX_VERSION` 等假环境变量 | 不存在 |
| 9 | `vocab_size` 自动从分词器读取 | 硬编码致 HIP kernel 崩溃 |

### Stage 2 LR 调优历程

| 尝试 | LR | 结果 |
|------|:---:|------|
| 1st | 4e-5 | 🔴 100 步崩塌 — 重复循环 + `Outlo：` 碎片 |
| 2nd | 1e-5 | ✅ 500 步恢复 · 1400 步最佳 — 柳小乐身份 + 对话流畅 |
| 3rd（续跑） | 5e-6 cosine | ⚠️ gn=0.38 但 LR 被压到 9.8e-7 |
| 4th（续跑） | 2e-6 恒定 | ⚠️ 2000 步过拟合 — 知识/创作退化 |
| **最佳** | **1e-5 · 1400 步** | **★ 身份认知 + 对话平衡最优** |

**教训：** 294M 模型的 Stage 2 训练窗口很窄——lr 高 4×（4e-5）直接崩塌，lr 低 5×（2e-6）学不动。1e-5 是甜点。1 epoch 已足够，续跑 0.5 epoch 开始过拟合。

## 七、MiniMind 对比总结

MiniMind（64M）证明了小模型可以做对话。关键差距：

| 维度 | MiniMind (64M) | 柳小乐 2.7 (294M) | 优势 |
|------|:---:|:---:|:---:|

| 注意力 | 标准 GQA | **DiffAttn + QK-Norm** | ✅ 柳小乐 |

### 13.3 根因机制

**主犯 MuonAdam：** Muon 大步长（μ=3e-3，AdamW 的 10 倍）通过前向计算链扰动 1D 参数的梯度方向。

**真凶 22400 词表：** CE 梯度 ∝ 1/22400，3.5× 稀释 vs MiniMind 6400。独立贡献 2.24 ema 损失（v23-h→v23-i 单变量证据）。

**副犯 DiffAttn：** `A = softmax(A1) − λ·softmax(A2)`，λ≈0.8 时有效梯度压缩至 ~80%。独立贡献 0.36 ema，但在 MuonAdam 下放大了。

✅ v23-b: NS5+λ冻结 → gn 0.3，非根因

✅ v23-d: StdAttn → gn 1.1→0.5，DiffAttn 在 MuonAdam 下无罪
✅ v23-e: 8K词表 → gn 2.4→0.5，vocab 在 MuonAdam 下无罪
✅ v23-f: 纯 AdamW+Std+8K → gn 峰值 1.7，MuonAdam 主犯确认
✅ v23-g: AdamW+Diff+22400 → gn 0.3-0.5，帮凶联手确认
✅ v23-h: AdamW+Std+22400 → ema 7.24，DiffAttn 副犯 $0.36

## 十六、v30 最终结论（2026-07-06）🔴

### v30b Base + SFT Stage 1 全链路废弃

| 阶段 | 步数 | ema | 实际表现 | 结论 |
|------|:---:|:---:|------|:---:|
| v30b Base | ~21000 | 3.22 | 任何输入→数学题格式 | 模式坍塌 |
| v30 SFT | 10608 | 2.66 | 输出 `#` `*` `步骤` 等格式化碎片 | Loss 作弊 |

### 表面错觉：ema 从 3.59 "救回来"到 2.66

Loss 下降的真相不是学会对话，而是模型发现了捷径——MiniMind SFT 数据中大量 markdown 教程的格式化 token（`#` `*` `步骤` `设计`）落在 mask=1.0 区域，输出它们就能把 loss 降下来。

**决定性证据：** `用户：你好` → top-10 预测无 `小`（`小乐：` 起始 token）。训练 10000+ 步后，模型从不认识对话格式。

### 根因链

```
MiniMind pretrain 数学应用题过多
  → Base 表征偏向数学题格式
    → SFT 从歪 Base 续训
      + MiniMind SFT 教程/攻略类占比过高
        → 模型找到格式化 token 捷径
          → ema 下降但对话能力为零
```

**MiniMind 数据全链路不可用。** 不是调参能解决的问题。

### 核心教训

1. **Loss 下降 ≠ 模型变好。** 在 masked loss 下，高频 token 捷径会掩盖真正的对话学习失败
2. **SFT 数据需要内容类型分类。** CJK 过滤 + 身份过滤不够，需要识别"对话 vs 教程"并剔除非对话
3. **Base 模式坍塌会传递。** Base 学歪后 SFT 无法纠正，必须从数据源头保证质量
4. **数据质量 > 数据量 > 调参。** 14GB 脏 SFT 数据不如 100MB 干净对话

### 关键认知转变

v30 失败后最初认为是 MiniMind 数据质量问题（数学题太多、教程太多），但仔细想来：

1. **MiniMind 作者用同样的数据成功了**——64M 模型已经能对话，说明数据不是不能用
2. **v30 加了额外变量**——Industry 40%（被证污染）、多助手标签（额外复杂度）
3. **一次失败不能排除随机性**——深度学习训练的随机种子影响可能很大

v31 的策略是**最简路径**：尽量模仿 MiniMind 作者的做法，去掉我们额外加的变量，看能不能复现他们的结果。

**但 Cosine LR 平滑了残留。** 后半段 lr 从 3e-4 降到 3e-5，模型在数据循环第二轮精细调整分布，身份映射自然稀释——18800 步衰减，20000 步消失。**不是被擦除，是概率被稀释到与其他续写方向拉平。**

**此前"Base 必须完全无 AI 身份污染"的推论被证伪。** 0.74% 的身份数据（经清洗后更少）在 1 epoch 下不足以刻入永久信念。Cosine LR decay 是天然的"平滑器"——后半段低 lr 让模型有机会重新平衡早期的锐利模式。
